**1️⃣ Overview**

The Secure Health Application is a Flask-based web system designed to store and manage patient medical data securely, provide role-based management tools, and generate visual analytics such as charts from medical metrics to support better statistical understanding and management.

The app supports two roles:
	•	Admin – fully secured system control for management.
	•	Patients – Fully secured access to their records but limited control over the rest of the system.

It uses:
	•	SQLite → login users
	•	MongoDB → patient medical records
	•	AI (Logistic Regression) → stroke-risk predictions generated by the AI and then reviewed by admin before informing patients or offering advise and treatment.

**7️⃣ Admin Guide (All Tools)**

Add a brand-new patient into the MongoDB database using the secure form.
Admin fills in the fields → system validates the input → record is stored safely.

2. Edit record
Search for a patient by their MongoDB _id, load their details, make changes, and save.
All updates go through server-side validation to prevent incorrect data.

3. Delete record
Allows the admin to permanently remove a patient from MongoDB.
A confirmation step is shown first to confirm and prevent accidental deletions.

4. Delete user account (SQLite)
Admin can remove any user login (except the main admin).
Uses SQLAlchemy to safely delete from the SQLite users table.

5. Change password
Admin can update their password using a secure form.
Passwords are re-hashed with Werkzeug before being stored making sure it is secure.

6. AI Predictions (Stroke-Risk Model)
AI insights automatically appear on the Admin Dashboard once the model loads successfully.
The system generates a clear and friendly message for each patient.
Displayed under the dashboard table column:
➡ AI Prediction
(Example: “AI Stroke Risk: HIGH (84% confidence) · doctor review is required before informing patient.”)

8️⃣ Patient Guide (All Tools)

1. Login to Dashboard
Patients log in using their secure account stored in SQLite.
Credentials are validated, sessions are protected, and passwords are hashed.

2. View Personal Health Record
Once patients are logged in, patients see their own record only — not anyone else’s.
This includes fields such as age, BMI, glucose level, hypertension, a contact to get in touch with for any concerns at all, etc.
Data is pulled directly from MongoDB for up-to-date results.

3. Protected Patient Dashboard
The dashboard gives the patient:
	•	A clear, friendly summary of their stored health information
	•	A simple layout that avoids overwhelming the user
	•	Basic instructions for understanding what each field means
	•	An easy access support number on their daashboard for any concerns, clarifications about their health record or account.

4. No AI Prediction Visible (Safety Feature)
Patients cannot see the AI stroke-risk prediction.
Only the admin dashboard displays AI-generated predictions.
This prevents unnecessary panic and false positives and ensures doctors/admins review results first before informing them.

5. Secure Session Handling
Patients remain logged in using a secure session cookie protected with:
	•	CSRF tokens
	•	Session timeout
	•	Brute-force login protection

The user is automatically logged out if inactive.

6. Logout
Patients can safely log out, which clears their session completely.

**9️⃣ Security Features**

✔ Password Hashing
Never storing plain-text passwords, every password is securely hashed using industry-standard algorithms, protecting users even if the database is compromised.

✔ CSRF Protection
All forms are protected with CSRF tokens to stop unauthorised request attacks and ensure that only genuine user actions are accepted.

✔ Session Hardening
	•	HTTPOnly (cookies can’t be stolen with JavaScript)
	•	SameSite=Lax (reduces malicious attacks)
	•	Timed session expiry (auto-logout if inactive)
	•	Secure cookies (ready for HTTPS deployment)
Together, these keep user sessions safe and prevent hijacking.

✔ Input Validation
WTForms plus manual checks stop unsafe characters, bad formats, and malicious inputs from entering the system.

✔ Rate Limiter
Blocks repeated failed logins to stop brute-force attacks and password-guessing attempts.

✔ Role-Based Access
Admin-only tools (insert, edit, delete, AI predictions, user deletion) are locked behind decorators so patients and normal users cannot access them.

✔ Security Headers
	•	X-Frame-Options: DENY
	•	X-Content-Type-Options: nosniff
	•	Referrer-Policy: strict-origin-when-cross-origin
	•	Content-Security-Policy 
These add browser-level protection against clickjacking, MIME spoofing, unsafe scripts, etc.

✔ Server-side Filtering
Ensures a patient only sees their own MongoDB record — never anyone else’s — preventing data leaks even if URLs are edited manually.

**🔟Databases Used**

SQLite → User Logins

Stores:
	•	username
	•	hashed password
	•	unique controls for account safety
	•	admin + patient login accounts
	•	fully structured authentication data for secure sign-in

SQLite is used because it’s lightweight, secure, stable and perfect for managing user authentication without mixing it with sensitive medical records.

⸻

MongoDB → Patient Records

Stores:
	•	age
	•	gender
	•	hypertension
	•	heart disease
	•	smoking status
	•	glucose level
	•	BMI
	•	stroke indicator
	•	flexible medical information that does not fit a strict SQL table

MongoDB is used for patient records because the data can vary a lot, sometimes missing fields, and requires the flexible NoSQL structure for efficient storage and querying.

**1️⃣2️⃣AI Stroke-Risk Prediction Model**

✔ Logistic Regression trained on medically relevant features
Uses the patient dataset stored in MongoDB, including:
	•	age
	•	hypertension
	•	heart disease
	•	glucose level
	•	BMI
These inputs allow the model to estimate the probability of a stroke occurring.

✔ Outputs a simple risk category
The model converts the prediction probability into clear, easy-to-understand levels:
	•	LOW – minimal predicted risk
	•	MEDIUM – signs that risk factors may be present
	•	HIGH – strong indicators based on combined features

Example:
AI Stroke Risk: "HIGH (84% confidence) Doctor review required before informing patient".

✔ Responsible AI Implementation
	•	AI results appear only on the Admin dashboard.
	•	Patients never see predictions directly to avoid unnecessary panic and fear.
	•	Admins/Doctors must verify and approve any AI-suggested risk before taking action.
	•	Ensures safe, ethical, and professionally-supervised clinical decision support.
